# Пробы серверных ручек

Четыре прогона без сети, без YDB и без облака. Проверяют то, что нельзя
проверить глазами на проде: разбор страниц площадок, поведение сборщика на
десятке сценариев, договор ручек `/lenta/*` и весь путь друзей — от права на
чужую строку до картинки аватара.

```sh
export PATH=$HOME/.local/node22/bin:$PATH      # node в ~/.local, не в PATH

node server/proby/proba-razbor.mjs             # разборщики страниц
node server/proby/proba-sbor.mjs               # сборщик: заходы, картинки, уборка
node server/proby/proba-lenta.mjs              # ручки ленты
node server/proby/proba-druzya.mjs             # друзья: право, дружба по коду, картинки
```

Код выхода: `0` — все проверки прошли, `1` — есть провалы, `2` — не из чего
проверять (нет страниц). Каждая проба печатает строку на проверку и итог.

Ничего ставить не нужно: серверные модули — CommonJS без зависимостей,
`npm ci` и сборка бандлов пробам не требуются.

## Проба друзей

`proba-druzya.mjs` держит поддельную YDB в памяти и стережёт то, за что
дороже всего платить. Право на строку: голого публичного адреса мало, чужой
секрет устройства не открывает чужую карточку, запрос без токена не обнуляет
привязку к аккаунту. Дружбу по коду: обе половины пары пишутся одним
запросом, опечатки не съедают право добавлять друзей, перебор кодов упирается
в предел. Картинку аватара: вес, подпись файла, вечный кэш только по совпавшей
метке версии, снятие. Двенадцать опечаток подряд и подмена чужой картинки —
отдельные случаи: оба раза беда была настоящей, оба раза проба её ловит.

## Откуда берутся страницы

`server/proby/stranicy/` — **синтетические** страницы, они лежат в
репозитории. Разметка настоящая (классы `tgme_widget_message_*`,
`<time datetime>`, `photo_wrap` с `background-image`, `service_message`,
`forwarded_from`, `link_preview`, `media_not_supported`), а тексты выдуманы:
чужие посты и чужие фотографии в публичный репозиторий класть нельзя.

Раньше пробы читали страницы, снятые с живых каналов в разведке 05.09.2026, и
путь к ним задавался переменной `LENTA_STRANICY`. Без неё пробы выходили с
кодом 2 — то есть работали только на одной машине и не годились для CI.
Переменная осталась как возможность прогнать те же проверки на живых
страницах:

```sh
LENTA_STRANICY=~/lenta node server/proby/proba-sbor.mjs
```

Имена картинок в чужом каталоге могут отличаться — проба берёт первое из
известных имён (см. `первыйФайл` в `obshee.mjs`). Проверки, которым нужны
файлы, которых у чужого каталога нет (раздел «Крайние виды каналов» и сверка
поломанных вариантов), при этом просто пропускаются.

### Как пересобрать страницы

```sh
node server/proby/stranicy/sozdat.mjs
```

Сборка **воспроизводима до байта**: никакого `Math.random`, никакой текущей
даты, вся арифметика картинок — целочисленная (`Math.sin` в разных сборках V8
может дать разный последний бит, и JPEG разошлись бы между машиной и
раннером). CI после прогона проб пересобирает страницы и падает, если
`git status` показывает разницу.

Поэтому **готовые `.html`, `.jpg` и `.xml` руками не правят** — правят
`sozdat.mjs` и пересобирают.

## Что проверяет каждая проба

### `proba-razbor.mjs` — разборщики (`server/lenta-razbor.js`)

* **Страницы Телеграма.** Сколько записей вышло у каждого канала, имя канала
  из шапки, форма записи по договору (дата до секунды, заголовок ≤ 120, текст
  ≤ 400 или `null`, отпечаток, хост картинки), порядок `data DESC`, счётчики
  отброшенного (чужой репост, свой репост, реклама, без содержания), фото без
  подписи → «Фото» без выдержки, ссылка в записи → только хост, премиум-эмодзи
  вместо буквы → запись без заголовка, «Записаться» и цена → тип `anons`,
  адресов в тексте и заголовке нет.
* **RSS Rutube.** 20 роликов, длительность и дата загрузки из `guid`, ни
  описаний, ни кадров (условия площадки), форма ссылок, RSS без `item` → пусто,
  не-RSS → не пусто и ни одной записи.
* **Смена вёрстки — порог здоровья.** Четыре поломки: нет `datetime` → «без
  даты 20 из 20» и ноль записей; переименован класс текста → «без текста»;
  переименован класс обёртки → ноль записей и НЕ «пусто»; фото без
  `background-image` → «без картинки 15 из 15 фото». Плюс сверка с файлами
  `slom_*.html`.
* **Крайние виды каналов.** Канал из одних фото без подписей разбирается
  целиком и признаётся здоровым: `bez_teksta = 0`, `s_tekstom = 0` (это F01 —
  раньше фото без подписи считались пропавшим текстом, а канал совсем без
  подписей отвергался целиком). Отними у одной записи и картинку — запись
  выходит пустой, и порог снова срабатывает: именно пустые записи рядом с
  пропавшим контейнером отличают смену вёрстки от фотоканала. Канал с чужим
  репостом и чужой рекламой: репост и три рекламы отброшены, id рекламы отданы
  сборщику, цена и «Записаться» помечены анонсом.
* **Правила фильтров** на синтетических блоках: стоп-слова, приветствие +
  ссылка, стикер без превью, своё и чужое превью ссылки, длительность видео,
  кривые и будущие даты, обрезка по слову, сущности HTML, управляющие байты.
* **robots.txt:** своя группа, группа `*`, самое длинное правило, пустой файл,
  адреса площадок, честный `User-Agent`.

### `proba-sbor.mjs` — сборщик (`server/lenta-sbor.js`)

Хранилище — `Map` с тем же договором, что у слоя YDB; бакет — `Map` ключ →
байты; часы и остаток срока функции — константы; сеть подделана.

* **Пережатие JPEG** своим `jpeg-js`: две копии (≤ 160 и ≤ 480 px), размеры,
  маленькое не увеличивается, PNG по сигнатуре → отказ, ключи бакета.
* **Первый запуск:** очередь включённых источников, порядок площадок, число
  новых по каждому каналу, «пусто по структуре» — это удача, сломанный
  источник не роняет остальные, 302 → ошибка, Rutube за сроком — только
  десятка, картинки только под согласием, два объекта на запись, состояние
  источника и строки журнала, `robots.txt` по разу на хост.
* **Второй запуск через 20 минут:** периоды, идемпотентность (ничего не
  удвоилось), `robots.txt` в тот же день не перепрашивается.
* **Правки** в окне 7 дней по отпечатку текста; правка записи старше окна не
  подхватывается; картинка при правке не перезаливается.
* **Сверка с источником:** запись, исчезнувшая между соседями, → `skryto`, её
  объекты удаляются из бакета; пропажа самой старой записи страницы — это
  конец листания, а не удаление; вернувшаяся запись не воскресает и не
  удваивается.
* **Скрыто модератором** → объекты долой при следующем заходе.
* **Картинки:** согласие появилось — подбираются записи с попытками 0; не-JPEG
  → три попытки и отбой, после третьей больше не просят.
* **Бюджет времени:** при остатке меньше порога все источники → `propusk`, без
  записей и без журнала. Порог — не круглое число, а сумма самого долгого пути
  до первой записи в базу: страница 30 с + сырьё почтальона 40 с + резерв
  записи 12 с = 82 с. Отдельно: если бюджет кончился ПОСЛЕ страницы, за сырьём
  не идём вовсе — заход честно кончается ошибкой сети и строкой журнала, а не
  обрывом функции на бакете (это F02 на дороге почтальона).
* **Тревога:** сутки без удачного опроса → строка `trevoga`, не чаще раза в
  сутки; молчащий, но доступный канал тревоги не даёт.
* **Уборка** «10 без срока + всё моложе 365 дней» без качелей: следующий заход
  не воскрешает удалённое и не заливает картинки заново.
* **Ручной запуск и разбор события:** таймер, `payload`, HTTP POST в base64,
  кривой `istochnik`, нормализация записи.
* **Слой YDB против миграции 007:** у каждого запроса все параметры объявлены
  и типизированы, таблицы, индексы и колонки — из миграции, литералы
  `Timestamp` без долей секунды, а в каждом `UPSERT` есть ВСЕ `NOT NULL`
  колонки (иначе YDB отвечает «Missing not null column in input»).
* **Находки ревью 8.8:** F02 (обрыв на картинках — записи уже в базе), F03
  (сетевой обрыв не тратит попытку, два подряд — стоп), F04 (заменили фото при
  том же тексте), F05 (дыра после простоя добирается назад по `?before=`), F08
  (страница целиком из рекламы — заход удачный, решения применяются), решение
  владельца про «скидку».

### `proba-lenta.mjs` — ручки (`server/lenta.js`)

Общая лента и лента управления, листание курсором, пределы и вид записи,
«есть новое», журнал «откуда», состояние сбора, жалоба и её пределы, скрытие
модератором, очередь жалоб и решения по ним, договор ответа при лежащей базе,
чистые функции (обрезка, хост, курсор, перемежение).

Отдельный раздел — **окно построения индекса** очереди жалоб. `ALTER TABLE …
ADD INDEX GLOBAL` в YDB строится в фоне, и пока индекса нет, запрос через
`VIEW` отвечает ошибкой схемы. На этом же индексе висит потолок ПУБЛИЧНОГО
приёма жалоб, поэтому без запасного пути человек получал бы на жалобу 503.
Проба включает «индекс не готов» и проверяет, что жалоба принимается,
очередь читается обходом таблицы, порядок «свежие сверху» держится, а в ответе
`/lenta/istochniki` появляется `indeks_zhalob: "stroitsya"`.

## Известное поведение, которое проба держит видимым

Канал, где **каждая** запись с фото или видео и подписи пропали все разом,
разборщику по разметке неотличим от честного фотоканала без подписей: пустых
записей не появляется, и порог здоровья молчит. Такую пропажу заметит только
человек. Всё остальное (текстовые записи вперемешку с фото — то есть все
четыре включённых канала) порог ловит: у сломанной разметки текстовые записи
выходят вовсе без содержания.

## CI

`.github/workflows/test.yml`, работа `proby-lenty`: три пробы на каждый push и
pull request. Ни секретов, ни сети, ни `npm ci` — только `node`. Последним
шагом страницы пересобираются из `sozdat.mjs` и сверяются с закоммиченными.
